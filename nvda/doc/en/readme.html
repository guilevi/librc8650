RC8650 / RC8660 (emulated)

An NVDA speech synthesizer that is an RC Systems RC8650 or RC8660 chip. Not a recreation of one: the chip's own firmware runs on an emulated Renesas M16C, and what you hear is the PCM its D/A converter would have produced. The voices, the text-to-speech and the command protocol are all the chip's.

The firmware image is RC Systems' copyrighted code and is not distributed with this add-on. Until you supply one, the synthesizer will not appear in NVDA's list.

Firmware

Firmware images are files ending in .srec or .srec.gz. Put them in the rc8650\firmware folder inside your NVDA user configuration folder, or use the settings page described below to add them. Updating the add-on does not remove them.

To choose one, open NVDA's settings and go to the RC8650 firmware category. The list shows every image found, each described by its chip, firmware version and board model, for example "RC8660 firmware 3.44, model 1". Select one and press OK; the synthesizer restarts on it. Add image copies a file into the firmware folder for you, and Open firmware folder opens it.

The voices and settings follow the chip. The RC8650 has eight voices and a formant setting from 0 to 9; the RC8660 has eleven voices and a formant setting from 0 to 99. When you switch between the two chips, the voice settings and the rate go back to the new chip's own defaults.

Voices

Eight on the RC8650, eleven on the RC8660, selected with the chip's own Voice command. Each one loads a preset inside the firmware, which is what gives it its character.

Settings

Selecting a voice snaps the settings below it in the list to that voice's firmware preset, so what the sliders say is what you hear. Move one and it overrides the preset for that voice; leave it alone and the preset comes through untouched.

SettingChip commandWhat it does
RatenS + nGOn the RC8650, twenty steps, roughly 116 to 395 words per minute: the chip has two ten-step speed scales, and this is both of them merged into one. On the RC8660, its own fourteen steps.
PitchnPThe chip's full 0–99 range.
InflectionnEHow much the pitch moves within a sentence. 0 is a monotone; the top is very animated.
VolumenV0–9, the chip's own.
TonenXBass, normal or treble.
ArticulationnALow slurs the speech, high makes it choppy.
Formant frequencynFShifts the whole vocal tract up or down, from 0 to 9 on the RC8650 and 0 to 99 on the RC8660. The chip does it by changing the speed of its sample clock, so a higher setting also speaks a little faster and higher.
ReverbnR0 is dry; higher values lengthen it.
Word delaynTExtra pause between words. The datasheet suggests it for listeners new to synthetic speech.
PunctuationnBHow much punctuation the chip itself speaks: all, most, some, or none.
Read numbers as numbersnBOff reads 123 as "one two three" instead of "one hundred twenty three".
Speak leading zerosnBOn, "007" keeps its zeros. On a screen this is content, so it is on by default even though the chip's own default is off.
Read four-digit numbers as yearsnBOn, 1492 is "fourteen ninety-two".
Output filter—Not a chip command: the reconstruction filter on the modeled output stage. The RC8650's audio pins are unfiltered, and the datasheet's own reference circuit is a 3 kHz low-pass — the default here. "Off" leaves the filter out.
Resampling—Not a chip command either: how the chip's 10 kHz samples become your sound card's. "Smooth" interpolates between them and keeps nothing above 5 kHz. "D/A staircase" holds each sample the way the real D/A pin does, at 48 kHz, keeping the faint mirror images that adds above 5 kHz for the output filter to soften; with the filter off, that is the bare sound of the pins. "BookPort" is one real unit, measured from a recording: its D/A's mirror images sit a little higher than the standard chip's, and its gentle 5 kHz filter leaves much of them in, while the voice itself keeps its usual pitch. BookPort replaces the output filter setting. To sound like that unit, also set Tone to Treble and raise the rate about two steps. A change takes effect from the next thing spoken.

Known limitations

  • Index reporting is accurate to about a tenth of a second. NVDA's index marks are the chip's own index markers: the chip reports each one as it reaches that point in the text, and the driver announces the index when the audio around it plays. Speech is fed to the sound card in 102 millisecond chunks and an index is announced when its chunk has played, so a highlight can be up to that late — small enough not to be noticed while reading, but it is not sample-exact.
  • One instance per NVDA process. The emulator core keeps global state, so only one engine can exist at a time. Switching away and back is fine.
  • English only. The chip's Spanish support needs an exception dictionary that this driver does not load.
